1项目总览

1.1 项目定位

Engchain3.0（工程链）是面向建筑行业的 B2B 供需平台：供方（建筑企业、服务商企业、专业个人）发布供给，需方查找、匹配并建立联系。当前数据层以浏览器本地存储实现，尚无服务端；Phase 0 仅做信息撮合——不抽佣、不托管资金，交易能力仅保留结构兼容。

App 端：三个入口页（首页、导览页、预览页）+ pages/（29 个已交付功能目录）+ 数据层脚本
管理后台：独立的后台工程（Vue3 + Element 风格），11 组 39 项已落地菜单
商业模式（Phase 0）：收入 = 企业认证年费与年度年审费 + 企业入驻费 + 信息解锁（98 积分/条）+ 增值道具与会员/运营包；破冰期对认证与入驻执行限时减免，成熟期按标准价；不涉及交易资金与托管
省级总代体系：S0–S5 六阶段招商能力已交付（省代/二级代理/台账/行为四套存储）

1.2 平台由谁在使用（一句话全景）

  • 供方：建筑企业（蓝V）、服务商企业（金V）、专业个人（建造师/工程师等）——需要发布供给、被需方找到、建立信任（认证 + 入驻）；
  • 需方：任何注册用户——搜索、浏览、收藏、解锁联系方式（98 积分/条，每月 3 条免费额度）、发起需求；
  • 平台侧：后台运营/财务/风控人员——审核认证与入驻、管理资金与发票、合规审计；
  • 渠道侧：省级总代与其二级代理——招商、发展企业入驻、按协议获取返佣。

2用户身份体系

2.1 四层身份模型与设计原则

一句话原则：单账号 · 资质挂载 · 外显分离 平台只有个人账号，不存在独立的企业账号；"企业身份"是个人账号上挂载的企业认证/入驻资质；权限只由资质派生，组织关系与外显身份对权限零影响。余额、积分、合同、订单恒挂个人账号。
图 1 · 用户身份体系架构（单账号 · 资质挂载 · 外显分离）新窗口打开 ↗
  • 账号层：个人账号是唯一法律、资金、权限主体，承担登录/余额/订单。
  • 资质层：个人资质（实名、专业、合伙人三条轨道）与入驻资质（建筑、服务商两类入驻），均由权威用户表派生并随其变更同步。
  • 派生层：一组只读规则把资质翻译成对外身份与页面能力门控，不做任何写入。
  • 组织/外显层：组织关系（老板/管理员/成员）与手动切换的展示身份，仅供展示与署名，不得写入资质。
设计红线（历史修复项，身份状态串写问题） ① 组织成员关系 ≠ 企业资质——员工不得因任职获得企业向权益；② 外显身份切换不改变任何权限；③ 代理新身份（未叠加个人合伙人）默认关闭旧返佣出口（由代理门控统一判定）。

2.3 五轨道成长模型（身份状态的演进逻辑）

图 2 · 身份成长路径（五轨道资质模型 + 驳回/终止）新窗口打开 ↗

驳回与恢复 认证/入驻被驳回按实付全额退费（入驻无保证金，不涉及解冻）；修改后可在已支付的前提下重提（不重复收费）；认证通过后当年不退，年度年审只顺延有效期；封禁为终态，后台可解封恢复。

2.4 游客与登录判定（S5 统一口径）

  • 判定游客：未登录，或身份状态为游客（全站统一判定，兼容早期字段）；
  • 游客可浏览供需、搜索、查看详情，但发布、解锁、认证、入驻、钱包、返佣等能力全部锁定；
  • 登录态与登录历史分开留存，具体键名见 §5.2。

4.1.4 设计意图总结

四条主线 ① 实名免费、企业认证年费与年度年审、入驻权益费：实名与个人资质免费，是为了不挡住供给入口；企业认证分两笔——首次核验收 ¥999（首年含当年年审），此后每年年度年审 ¥599；入驻按次收费，买的是发布与展示权益。三者价格随阶段变化——破冰期限时减免（建筑 0 元、服务商 5 折、企业认证与年审全免），成熟期按标准价执行；标准价始终并列展示，期后规则在生效当天告知，避免“免费”被理解为定价；
② 认证在前、入驻在后：认证管主体身份是否真实，入驻管能否拿到发布与展示权益，两道关口各管一件事，不用可退资金代替审核；
③ 分级解锁：把联系方式这类高价值信息按稀缺度定价，基础浏览与发布保持免费；
④ 区域代理：把获客与招商外包给本地渠道，用总盘分成替代固定人力成本。

6.1 认证与入驻（两级审批全链路）

图 4 · 认证与入驻审批全链路时序新窗口打开 ↗
环节规则
两期定价破冰期（出厂默认，截止 2027-09-30）建筑入驻 ¥0、服务商入驻 ¥1,499（5 折）、企业认证 ¥0；成熟期建筑 ¥3,999、服务商 ¥2,999、企业认证 ¥999 首次核验、年度年审 ¥599/年。减免只作用于本期实付，标准价始终并列展示，期后按标准价续费。到期后即使阶段开关仍停在破冰期，系统也按截止日判定为成熟期，不再免费。认证费按阶段由统一取价出口给出（破冰期 0 / 成熟期 999），年审费由另一取价出口给出（破冰期 0 / 成熟期 599），认证页、认证中心、资料准备页、认证结果页同读一处；渠道对账页不依赖主数据层，按同一阶段标记与截止日自行判定；年审单列，与首次核验分开收取、分别退
