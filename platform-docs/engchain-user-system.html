1项目总览

1.1 项目定位

Engchain3.0（工程链）是面向建筑行业的 B2B 供需平台：供方（建筑企业、服务商企业、专业个人）发布供给，需方查找、匹配并建立联系。当前数据层以浏览器本地存储实现，尚无服务端；Phase 0 仅做信息撮合——不抽佣、不托管资金，交易能力仅保留结构兼容。

App 端：index.html / home.html / preview.html + pages/（30 个功能目录）+ js/（数据层）
管理后台：admin-vue/（Vue3 + Element 风格），12 组 42 项菜单
商业模式（Phase 0）：收入 = 企业入驻费 + 信息解锁（98 积分/条）+ 增值道具与会员/运营包；交易与托管仅结构兼容
省级总代体系：S0–S5 六阶段招商能力已交付（省代/二级代理/台账/行为四套存储）

1.2 平台由谁在使用（一句话全景）

  • 供方：建筑企业（蓝V）、服务商企业（金V）、专业个人（建造师/工程师等）——需要发布供给、被需方找到、建立信任（认证/入驻/保证金）；
  • 需方：任何注册用户——搜索、浏览、收藏、解锁联系方式（98 积分/条，每月 3 条免费额度）、发起需求；
  • 平台侧：后台运营/财务/风控人员——审核认证与入驻、管理资金与佣金、合规审计；
  • 渠道侧：省级总代与其二级代理——招商、发展企业入驻、按协议获取返佣。

2用户身份体系

2.1 四层身份模型与设计原则

一句话原则：单账号 · 资质挂载 · 外显分离 平台只有个人账号，不存在独立的企业账号；"企业身份"是个人账号上挂载的企业认证/入驻资质；权限只由资质派生，组织关系与外显身份对权限零影响。余额、积分、合同、订单恒挂个人账号。
图 1 · 用户身份体系架构（单账号 · 资质挂载 · 外显分离）新窗口打开 ↗
  • 账号层：个人账号是唯一法律、资金、权限主体，承担登录/余额/订单。
  • 资质层：个人资质（AuthStore · engchain-auth：实名/专业/合伙人）与入驻资质（EntryStore · engchain-entry：建筑/服务商入驻），均从权威用户表快照同步。
  • 派生层：deriveIdentity / entryAccess 等只读纯函数，把资质翻译成页面能力门控。
  • 组织/外显层：组织关系（老板/管理员/成员）与手动切换的展示身份，仅供展示与署名，不得写入资质。
设计红线（历史修复项，身份状态串写问题） ① 组织成员关系 ≠ 企业资质——员工不得因任职获得企业向权益；② 外显身份切换不改变任何权限；③ 代理新身份（未叠加个人合伙人）默认关闭旧返佣出口（AgentAccess 门控）。

2.3 五轨道成长模型（身份状态的演进逻辑）

图 2 · 身份成长路径（五轨道资质模型 + 驳回/终止）新窗口打开 ↗
轨道（IDENTITY_STATE_KEYS）含义典型路径
realname实名认证二要素 + 活体自动核验 → 即时通过
personal-entry个人入驻提交专业资质+简历 → 审核 → pro
partner个人合伙人申请分销意向 → 审核 → partner
enterprise企业认证5 维资料 → 后台审核 → verified

每轨状态取 locked / todo / review / reject / done 五态；处理优先级为 enterprise → entry → partner → personal-entry → realname；"五轨道点亮数"（doneN）0–5 用于身份卡展示。

驳回与恢复 认证/入驻被驳回自动退费并解冻保证金；修改后可在已支付的前提下重提（不重复收费）；封禁为终态，后台可解封恢复。

2.4 游客与登录判定（S5 统一口径）

  • 判定游客：UI.state.loggedIn === false 或身份状态为 guest（DataBus.isGuest 统一口径，兼容旧字段）；
  • 游客可浏览供需、搜索、查看详情，但发布、解锁、认证、入驻、钱包、返佣等能力全部锁定；
  • 登录态存于 engchain-state（account），登录历史存 engchain-history。

4用户特征与属性

4.1 用户特征（业务画像与设计意图）

本节描述平台用户群体的业务特征：谁在使用、以什么身份使用、核心诉求是什么，以及这些特征如何决定系统的规则设计。个别账号的画像样本见 §9，不作为本节内容。

4.1.2 五组关键群体特征

特征业务表现系统影响
资质驱动信任工程承接先看资质等级、业绩、安许与建造师备案；无资质无法承接，用户不敢直接对接企业认证 5 维核验、资质证书与业绩档案、保证金门槛、蓝V/金V 标识
低频高客单单个项目金额大、成交频次低、决策周期长（招投标流程）以年费与订阅为主（入驻年续、会员年费、运营包年付），少用高频促销；采用按条计价的线索包而非月度无限量
强区域属性施工能力受属地备案与区域保护限制，跨省经营需要本地主体省—市两级代理、省份名额与区域独家、本省免解锁、二级必须同省

4.1.3 特征到系统设计的映射

特征对应设计设计意图
资质驱动信任认证 5 维免费核验 + 资质与业绩结构化展示 + 保证金以低成本认证扩大可信供给，把“信任”做成基础设施而非收费点
低频高客单入驻年费、会员年费、运营包年付（送 2 个月）用订阅锁定全年关系，替代单次高价成交的不确定性
强区域属性省代独家 + 二级同省 + 名额下限 10用区域代理替代全国直营获客，降低本地化落地成本
角色双向单账号 + 资质挂载 + 身份派生避免账号体系分裂，余额、合同、订单恒挂个人
信息不对称分级解锁（98 / 198 / 29 积分）+ 每月 3 条免费额度高价值信息按稀缺度收费，基础连接保持免费

价格敏感但付费点集中会员 0.8x/0.7x/0.5x 折扣、批量充值 5.8 / 4.3 折不直接降价，用权益折扣与批量档降低单次决策成本

4.1.4 设计意图总结

四条主线 ① 免费认证 + 收费入驻：先把供给池做大，再用入驻费与保证金筛选真实主体；
② 保证金替代风控：用可退资金换取信息真实性，比逐单人工审核更可规模化；
③ 分级解锁：把联系方式这类高价值信息按稀缺度定价，基础浏览与发布保持免费；
④ 区域代理：把获客与招商外包给本地渠道，用总盘分成替代固定人力成本。
