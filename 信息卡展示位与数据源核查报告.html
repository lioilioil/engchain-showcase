连通性判定口径
连通数据源合并了 MOCK.catalog 对应子数组 且 localStorage['engchain-supply']（SupplyStore active）中用户发布条目，与标准 mergedList() 同源
不连通只读 MOCK.xxx 子数组、未合并用户发布数据；或 mock 池与目标 bizKey 无交集导致结果恒空
独立数据localStorage 快照直渲（收藏/历史/积分日志），不回查 catalog，数据可能与源不同步
静态HTML卡片内容直接写死在 HTML 中，非数据驱动
核心发现（按严重度）
P0发现页「资源」Tab mock 数据恒空：mergedList mock 基准池误用 byFlow('match')（5类供需），再被 franchise/trade/personnel/talent 过滤，4 类资源卡 mock 层查无数据

数据断连 / 不一致问题清单

P0-01致命·数据恒空发现页「资源」Tab mock 数据恒空
问题：supply/list.html 的 mergedList() mock 基准池写成了 MOCK.byFlow('match')（仅 material/labor/equipment/cooperation/agency 5类供需），而一级 Tab=「资源」时用 RES_KEYS=[franchise,trade,personnel,talent] 去过滤——这4类不在 match 池内，因此资源 Tab 的 mock 数据恒为空，只能展示 SupplyStore 里用户发布的资源类条目。
影响：资质招商/建企买卖/企业招聘/人才求职 4类卡片在发现页资源 Tab 下无平台内置数据。
位置：pages/supply/list.html 行183-194 mergedList()

// pages/all-listings.html 行262-269（标准定义）
function mergedList() {
  var mock = (window.MOCK && MOCK.catalog) ? MOCK.catalog.slice() : [];
  var active = readActiveSupplies().map(normSupplyItem);
  var seen = {}, out = [];
  active.forEach(function (x) { if (!seen[x.id]) { seen[x.id] = true; out.push(x); } });
  mock.forEach(function (x) { if (!seen[x.id]) { seen[x.id] = true; out.push(x); } });
  return out;
}
