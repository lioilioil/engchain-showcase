01任务背景与排查范围

02四大排查目标体系

所有检查项与修复决策，都必须能映射到以下四类目标之一。无法映射的"个人偏好式改动"不进入本期。

目标 A · 视觉一致性目标（Design Token 零漂移）

全量页面严格复用 app.css V3.3 令牌：暖米纸感底 5 级、古铜金主色单一角色、5 级文字层次、四级圆角、多层阴影、明/暗双主题。任何硬编码色值、孤立字号、自创圆角/阴影、与主题令牌不符的写法都视为问题。验收：grep 无散落硬编码色值；暗色下对比度全部 ≥ 4.5:1；同角色组件（卡片/按钮/标签/导航）跨页观感一致。

目标 B · 交互体验目标（可点、可懂、有反馈）

所有可点击元素热区 ≥ 44×44px；主操作唯一且视觉权重最高；每个动作有即时反馈（按压态/loading/成功失败 toast/结果态）；表单有校验与错误提示；空态/错误态/加载态三态齐备且文案引导下一步。验收：随机抽页点测，无"点了没反应/不知道成没成/不知道下一步去哪"的断点。

目标 C · 流程连贯性目标（路径无断点、无死路、无歧义跳转）

以真实业务主路径走查：注册登录 → 浏览发现 → 解锁/发布 → 在线下单支付 → 资金钱包/发票 → 我的/认证/入驻 → 分销。每条路径上的页面跳转、返回层级、状态衔接、跨页命名一致。重点消除：链错页面、返回层级错乱、A 页叫"X"B 页叫"Y"、按钮跳错业务场景。验收：主路径走查脚本全程无死路、无错跳、命名全程一致。

目标 D · 低用户认知门槛目标（一眼懂、不用想）

信息层级 3 层以内；卡片标题即语义；关键数字（价格/金额/进度/状态）一眼可读；图标+文案双编码；专业术语（工程行业）配解释或示例；无歧义缩写。营销/提示不抢主任务。验收：新用户视角抽页，首屏 3 秒内能说出"这页是干嘛的、我能做什么"。

03排查维度与检查清单

对每个页面状态，按以下 7 个维度逐项打勾/记录问题。每个检查项标注所属目标（A/B/C/D）。

3.1 视觉一致性（目标 A）

检查项判定标准
颜色令牌无硬编码 #xxxxxx/rgb()，全部走 --bg/--primary/--text-* 变量
字号字阶标题/正文/辅助文字落在 V3.3 五档字阶内，无随机 13px/15px 混用
圆角/阴影卡片 r-l/r-m、按钮 r-full、浮层 shadow-float，无自创圆角
组件一致导航栏、TabBar、卡片、按钮、标签、开关、弹窗跨页规格统一
暗色适配明→暗切换无白块/黑字丢失/对比度不足，无"先亮后暗闪烁"
间距栅格页面边距 16px、卡片间距、列表行高统一，无忽松忽紧

3.2 交互与反馈（目标 B）

检查项判定标准
热区尺寸可点区域 ≥ 44×44px；返回 icon、删除/确认按钮足够大可点
主操作权重每页唯一主 CTA，视觉权重最高（金底/大圆角/位置底部或右上）
操作反馈按压态 scale/变暗、提交 loading、成功/失败 toast、结果页
表单校验必填/格式/范围即时提示，错误位置明确，不静默失败
三态齐备空态（插画/文案/引导按钮）、错误态、加载态，不出现白屏/半截

3.3 动效与节奏（目标 A/B）

检查项判定标准
动效克制仅用于状态反馈与页面转场，无炫技式动画；时长 ≤ 300ms
减少动态尊重 prefers-reduced-motion；暗色切换无逐页闪烁
转场一致页面进入/弹层/Tab 切换动效全 App 同一套缓动曲线
进度反馈长操作（支付/上传）有进度或骨架屏

3.4 流程连贯与导航（目标 C）

检查项判定标准
跳转正确每个链接 href 指向正确业务场景（例：团队≠分销、充值协议≠积分）
返回层级history.back() 层级正确，深层页可安全返回，不退到白屏
命名一致同一事物跨页同名（导航标题/页内标题/入口链接不重复不冲突）
无死路每个页面至少有一个出口（返回/主操作/下一步）
状态衔接提交结果页能回到列表/继续任务，不丢失上下文

3.5 信息层级与认知（目标 D）

检查项判定标准
首屏即懂标题+副标题 3 秒说明"这页做什么"
关键数字金额/价格/进度/状态突出，单位与币种清晰
文案规范无错别字/术语无解释/营销话抢占主任务；按钮文案动作明确
卡片不溢出长文本省略/渐隐，不撑高卡片；信息不换行错乱
营销位克制营销卡片按规则插位，不挡主任务、不在底部突兀插入

3.6 业务与商业模式校验（目标 C）

从商业模式视角核对：付费墙位置是否合理（该付费才付费、该免费体验不设卡）、价格/积分/费率数字与 data.js 常量一致、意向金/托管/退款规则表达准确、分销与会员权益闭环完整、不存在与收费逻辑冲突的免费泄露。

3.7 工程可维护性（前端）

HTML 语义结构、脚本无 console 报错、id/class 命名一致、无重复内联样式块、引用资源路径正确、暗色变量无遗漏、滚动高度链（flex/min-height）正确。

04执行计划（阶段 × 分批）

4.1 四阶段划分

P0 · 基线冻结固化 V3.3 令牌与通用组件清单，产出"检查标尺"
P1 · 全量扫描按模块分批截图+人工体检，登记问题清单
P2 · 分级修复P0 阻断→P1 体验→P2 美化，逐批改逐批验
P3 · 回归验收全量复扫+主路径走查+暗/亮双态终验

4.2 P1 分批顺序（按业务主路径优先级）

批次模块理由
第 1 批首页 / 发现 / 详情 / 搜索 / 消息流量入口与首屏印象，决定第一观感
第 2 批钱包 / 在线下单 / 订单 / 分销直接涉及支付与转化，商业模式敏感
第 3 批我的 / 个人中心 / 设置 / 认证入驻用户停留深、功能密集、状态多
第 4 批发布工作台 / 协议 / 帮助 / 账户 / 其他长尾页面，统一对齐即可
每批产出：页面截图（亮+暗）+ 问题清单表（页面/维度/问题/严重级/建议改法）。P1 只记录不改，确保问题登记完整后再统一进入 P2，避免边扫边改遗漏。

05问题分级与修正闭环流程

级别定义示例
P0 阻断功能不可用/错跳/白屏/数据渲染失败/严重遮挡/暗色破裂按钮跳错页、列表不渲染、底部悬浮盖住内容
P1 体验可点但难懂/无反馈/层级乱/热区小/命名不一致点了没反馈、主操作不突出、同物异名
P2 打磨观感优化/间距/对齐/文案润色/动效统一字阶微调、间距统一、空态插画升级

5.1 单问题闭环（每个问题必走）

① 登记页面/截图/维度/级别/复现路径
② 定级P0/P1/P2，映射目标 A–D
③ 修复最小改动，只改该问题
④ 复验真实浏览器截图回读
⑤ 回归相关联页面+主路径不被破坏

每个修复改文件 → 起浏览器截图 → 肉眼回读 → 确认无新问题四步缺一不可；禁止只改代码不看渲染结果。

06多角色交叉验证机制

每个批次完成后，由五类视角交叉评审同一组截图与问题清单，任一视角提出未覆盖项则回补，不允许单视角自说自话。

08边界、风险与确认事项

本阶段只出报告，不修改任何页面。执行须在你确认后启动。执行期边界：
  • 不改业务逻辑与数据层（js/data.js、stores、状态机的规则不动，只做 UI/UX/排版/交互/一致性修复）；
  • 保留已逐页确认的修复（约 30 项），本报告只做横向体检，不回退；
  • 设计决策不擅自扩张：涉及信息架构改名、业务规则、收费逻辑的争议项列为"待定"，先问后改；
  • 验证方式：真实浏览器（390×844 deviceScaleFactor 2）亮/暗双态截图回读，不凭代码自证。

需你确认后再启动：① 四大目标与检查维度是否认可；② 四阶段 + 四批顺序是否认可；③ 问题分级标准是否认可；④ 是否存在需额外保护的页面/逻辑。确认后我即按 P0→P3 顺序执行。
