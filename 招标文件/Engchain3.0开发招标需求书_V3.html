一、项目概况

项目背景：“工程链（ENGCHAIN）”是面向建筑工程行业的综合服务平台，围绕建筑企业、持证人才与服务机构，提供供需信息发布与对接、线索付费解锁、在线交易、分销推广、中介服务、资质招商、建企买卖、人员招聘等能力。平台已完成为期多轮的前端产品设计开发（3.0 版本），形成了完整的用户端页面与管理后台页面资产，但当前均为静态 HTML 原型，尚无后端服务、数据库、支付与多端能力。

建设目标：将现有静态原型改造为可上线运营的商业化产品：Web 用户端与官网、Web 管理后台、4 个小程序（微信/小红书/抖音/支付宝）、3 个 App（安卓/iOS/鸿蒙）；补齐后端服务、数据库、支付结算、实名认证、电子签、消息推送等基础设施；保留现有全部业务板块并优化流程、性能与体验，形成可运营、可管理的完整产品闭环；部署于腾讯云并正式发布。

招标方式：邀请比价。甲方定向邀请候选软件公司，乙方依据本需求书及《报价表》填报报价并回传，甲方综合评审后确定合作方。

预算与工期：项目预算人民币 15 万元（含税总价上限）；项目工期 3 个月（自合同签订之日起）。

二、现有资产与参考实现

1. 用户端：29 个业务模块、98 个以上页面，覆盖首页、认证、钱包、订单、发布、分销、中介服务、资质招商、建企买卖、人员招聘、消息、个人中心等全部板块。

2. 管理后台：数据总览、用户管理、运营管理、财务管理、分销管理、中介托管、风控合规、系统配置 8 大模块页面（框架级参考）。

3. 资产形态：静态 HTML/CSS/JS 页面，含视觉系统规范（V3.3）与高保真交互原型。

4. 随本标书提供现有前端源码包（ZIP），作为参考实现。

使用约定：乙方应以参考实现为产品基准（页面结构、视觉风格、信息架构与核心交互原则上保持不变）；参考实现用于说明产品形态与交互细节，不构成对后端能力、数据模型、运营机制和管理后台功能的限制，本需求书的功能需求描述为开发范围的权威依据；乙方负责后端服务与数据模型设计、数据库建设、支付与第三方集成、多端适配开发、数据迁移、部署上线；如因技术实现确需调整页面细节，应保持整体视觉与信息架构一致，并提前与甲方确认。

三、交付形态与技术架构要求

3.1 交付形态

端定位功能范围
Web 用户端完整主端全部业务功能，兼容 PC 与移动端浏览器
Web 管理后台运营与管理产品运营、财务资金、风控合规、项目与企业运营、系统管理
微信 / 小红书 / 抖音 / 支付宝小程序轻量引流版用户注册/登录、活动页、主列表页、详情页（含 App 跳转）等基础获客功能；支付宝小程序含支付宝登录与支付
Android / iOS / 鸿蒙 App完整主端全部业务功能、消息推送、应用市场上架支持

说明：小程序承担获客与导流角色，核心交易、资金与复杂业务流程在 Web/App 完整主端完成；详情页在小程序内做信息展示，并支持跳转 App 或引导下载。

3.2 技术架构要求

  • 前后端分离架构，后端提供 RESTful API（含鉴权、限流、日志）；
  • 数据库 MySQL + Redis（缓存/会话）；文件与图片使用对象存储（腾讯云 COS）+ CDN；
  • 短信、消息推送等使用腾讯云服务；部署环境为腾讯云（CVM/数据库/COS/CDN/SMS 等），支持 HTTPS、灰度发布与快速回滚；
  • 跨端技术选型要求：小程序与 App 建议采用生态成熟、可交付性强的跨端框架（如 uni-app、Taro 等基于 Vue/React 的成熟方案）；
  • 不推荐 uni-app x：该框架发布较新，第三方插件生态（支付、推送、IM、地图等）、组件库与行业案例积累尚不成熟，开发团队熟悉度普遍较低，在 3 个月交付窗口内存在较高的适配与排障风险；
  • 鸿蒙 App：乙方应在投标方案中明确鸿蒙端的实现方案（成熟跨端框架的鸿蒙支持或 ArkTS 原生实现）及可行性论证；
  • 最终技术选型由乙方在投标方案中说明理由，甲方以生态成熟度、可交付性、团队能力为主要评审依据。

七、投标要求与报价说明

邀标比价流程：1. 甲方发放本需求书与《报价表》；2. 乙方在约定时间内回传《报价表》及投标材料；3. 甲方评审并商务谈判；4. 确定合作方并签约。

投标材料：《报价表》（Excel 填报后回传）、营业执照、同类项目案例（1-2 个，附截图或链接）、团队配置与排期承诺、技术选型说明（含鸿蒙端方案）。
