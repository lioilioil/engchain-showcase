**总评：骨架专业，血肉待熟。** 交易模型（撮合 + 意向金 + 资金托管 + 里程碑释放 + 佣金 + 质保金 + 纠纷仲裁）是符合商业规则的成熟框架，三端闭环已可演示；但按"专业 App + B 端用户习惯"标准，仍有 **4 类系统性缺口**：

| 维度 | 评级 | 一句话结论 |
|---|---|---|
| 商业模式与商业规则 | ★★★★☆ | 资金托管与"规避二清"模型正确；佣金保底为死逻辑、收入结构单一 |
| 用户侧（需求方）路径 | ★★★★☆ | 三步下单向导专业；缺服务对比、合同/发票、进度通知 |
| 服务商侧（机构）路径 | ★★★☆☆ | 工作台信息密度已达标；缺经营漏斗、定价管理、报价提醒 |
| 平台侧（运营）路径 | ★★★☆☆ | 六 Tab 齐全；原生 prompt 弹窗不专业、缺证据流与趋势报表 |
| 理解门槛（B 端小白） | ★★★☆☆ | 术语解释已有雏形；缺统一"交易保障"心智与首次引导 |

## 二、商业模式评估（是否符合商业规则）

### 2.1 价值网络：正确

```
服务/方案/交付成果
建筑企业(买方) ←────────── 中介机构(服务商)
     │                          │
     └──────── 平台(Engchain) ───┘
    撮合与信任  资金与风控  规则与监管
```
平台不做服务本身，做"撮合 + 信任背书 + 资金安全 + 规则执行"——这是中介行业平台的标准范式，方向正确。

### 2.2 收入模型：基本成立，有 3 处待完善

**现状（代码实证）**：
- 撮合佣金：阶梯费率 8%→3%（0/5万/20万/50万/100万 五档，`data.js:1092`），服务商侧扣、用户侧零扣减；
- 入驻费 ¥29,999（破冰期 ¥14,999）；增值道具（置顶/线索包/经营工具，`data.js:1103` 已配置）；
- 远期：资金沉淀（托管在途期间的利息/合作收益）。

**3 处不成熟**：
1. **佣金保底是死逻辑**（本次核对确认）：`commissionRate` 中 `amount>=500000 && fee<10000` 才保底；但 ≥50 万档费率为 4%（50 万×4%=¥20,000 > ¥10,000），**任何金额都不可能触发保底**（`stores.js:1124`）。结论：要么删除该规则，要么改为"小额单最低佣金下限"（如单笔佣金下限 ¥100/¥500），避免规则存在却永不生效的观感问题。
2. **费率按金额档、不按类目**：真实中介行业按服务类目定价（资质代办按标的额比例、工商注册按件收费）。建议后续支持"类目费率覆盖"（数据层已预留 `minServiceFee` 结构）。
3. **收入结构单一**：成熟平台还有广告/会员/供应链金融，demo 可不做，但路线图要写明。

### 2.3 资金与合规：模型正确，是板块最大的专业亮点

- "钱不过手、按里程碑释放、规避二清"（`data.js` 托管文案 + Mediation 状态机）——符合监管方向；demo 用 Ledger 模拟且**资金守恒可对账**（充值→意向金→托管→释放→退款全链路已实测一致，且修复了"充值不走 Ledger"的双账 bug）。
- 兜底机制齐全：意向金 7 天提醒/30 天自动退、托管 7 天提醒/15 天自动全额退（本轮新增）、里程碑 14 天自动确认、纠纷三态仲裁。
- **注意**：真实落地需接入持牌支付机构/银行存管（demo 为本地模拟，交付说明中已注明此边界）。

### 2.4 撮合模型（需求广场双向撮合）：创新正确，缺 4 个运营机制

已实现：需求发布→机构报价→接受报价→下单锁报价（`DemandStore` 状态机 open→quoted→matched→closed）。这是双边市场成熟化标志。

专业缺口（运营视角）：
1. **需求匿名性**：企业主发布需求=暴露采购意向，真实平台默认匿名（报价后才互见），需确认并落地；
2. **报价排序/比价**：当前按时间序，应支持按价格/信用分排序；
3. **过期需求转人工**：7 天过期后应自动转入平台顾问线索池（`LeadStore` 平台线索），形成人工闭环——正好承接"联系平台顾问"留资；
4. **平台对报价质量无干预**：缺虚假报价/低价钓鱼的抽检或信用约束机制。

### 2.5 双边信用体系：雏形有，未参与排序

- 评价星级 1-5（本轮从硬编码 5 分修复为可交互）+ 信用分 `svcCreditOf`（基础 60 + 履约 40）存在；
- 缺口：信用分未参与报价排序/推荐权重；无买方信用（防恶意纠纷/拒付，跳单规则 `jumpContract` 已配置但无执行页面）。

## 三、三端执行路径审查（专业 / 成熟 / 适用 / B 端习惯）

### 3.1 用户侧（建筑企业主）★★★★☆

**路径 A（货架下单）**：广场 → 详情（报价/案例/流程/退款条款）→ 三步下单（选服务商→确认金额→付意向金）→ 托管 → 里程碑验收 → 结算 → 评价
**路径 B（需求发布）**：发布需求 → 收机构报价 → 比价 → 接受报价 → 下单（金额锁定机构报价）

**做得对（符合 B 端习惯）**：
- 三步向导把"高客单价决策"拆解成可操作的步骤；
- "意向金启动前可退"话术前置，降低首次信任门槛；
- 里程碑金额可视化、14 天自动确认兜底，符合建筑行业长周期项目习惯。

**不成熟点**：
| # | 问题 | 影响 |
|---|---|---|
| U1 | 无服务/报价横向对比卡 | 企业主多机构比价是刚需，当前只能逐个看 |
| U2 | 订单进度无主动通知 | B 端习惯是微信/短信被动提醒；demo 至少做站内消息 + 角标 |
| U3 | 无合同/发票模拟 | 建筑企业走账必走合同与发票，缺失直接拉低真实感 |
| U4 | 退款无"到账凭证"展示 | 退款闭环感弱 |
| U5 | 平台顾问跟进不可见 | 留资后无"顾问对话"承接，信任链断 |

### 3.2 服务商侧（中介机构）★★★☆☆

**路径**：入驻两级审核 → 发布服务（待审）→ 工作台（近7日经营/线索/订单/保证金/服务/需求广场/收益）→ 接单/拒单 → 交付 → 提醒验收 → 收款 → 提现

**做得对**：工作台已是专业后台雏形（线索四态、订单收入佣金透明、需求广场可报价可撤回、履约保证金三档、三步经营指引）。

**不成熟点**：
| # | 问题 | 影响 |
|---|---|---|
| S1 | 无经营漏斗（线索→报价→成交转化率） | 机构老板最关心转化，当前只有罗列没有分析 |
| S2 | 无定价管理（批量调价/促销/置顶道具入口） | 增值道具已配置但无使用入口 |
| S3 | 需求广场无"新需求推送/类目订阅" | 报价时效性弱，接单率低 |
| S4 | 履约体验：无批量交付、无里程碑提前量提醒 | 多项目并行时效率低 |
| S5 | 收益→提现链路未做端到端演示 | 收款闭环未完全验证 |

### 3.3 平台侧（运营）★★★☆☆（本轮新建后）

**路径**：入驻两级审核 → 发布审核 → 需求管理 → 纠纷仲裁 → 佣金报表 → 资金监管

**做得对**：六类运营刚需全覆盖，仲裁三态（放款/退款/分账）符合规则。

**不成熟点**：
| # | 问题 | 影响 |
|---|---|---|
| P1 | **5 处原生 `window.prompt`**（驳回原因×2/下架原因/仲裁说明/退款比例） | 不专业、无验证、已实测阻塞自动化流程 |
| P2 | 审核无证据流（看不到服务商资料/服务内容/信用摘要） | 运营无法决策 |
| P3 | 报表无趋势/漏斗（GMV、转化、纠纷率） | 运营专家视角必须有趋势图 |
| P4 | 需求管理缺质量运营（虚假需求标记/过期转人工） | 需求池质量无治理 |
| P5 | 规则不可配置（佣金/超时/质保在 data.js 写死） | 成熟运营台惯例：规则可配置 |
