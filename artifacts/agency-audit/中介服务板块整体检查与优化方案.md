# 中介服务板块 · 整体检查与优化方案（产品经理 + UI/UX 视角）

> 版本：v1.0（待用户确认） ｜ 范围：用户侧 / 服务商侧 / 平台侧 ｜ 原则：先思考 → 定目标 → 深度检查 → 修改计划 → **经确认后执行**
> 本方案基于对 Engchain 全项目代码的实际勘察（数据层 js/data.js → common.js → stores.js → databus.js → domain.js，以及中介板块全部相关页面）产出，所有结论均标注证据与来源，可直接复核。

## 一、执行摘要（30 秒读完）

Engchain 的中介服务板块**交易主链路已相当完整且专业**（意向金→托管→里程碑→结算的状态机、佣金阶梯、质保金、信用分、留资线索均有真实代码支撑），但存在三类问题：

1. **平台侧几乎缺失**：审核、佣金报表、资金托管在途、纠纷仲裁都只有数据层方法、没有运营后台页面，三端中"平台"这一角是空的，导致纠纷是死胡同、审核不可演示。
2. **若干真实逻辑缺陷**：佣金保底 ¥10,000 会让小额订单佣金倒挂；托管单无"超时未接单"机制；评价硬编码 5 分等。
3. **体验存在理解门槛与零散感**：专业术语（金V/托管/意向金/里程碑/质保金）解释分散、部分交互是"僵尸按钮"、三端视觉未完全统一。

**建议动作**：新建平台运营后台演示页 + 修复 P1 级逻辑缺陷 + 统一三端视觉与术语，形成"用户下单→服务商履约→平台监管"的完整可演示闭环。详细计划见第七节，需您确认的决策点见第八节。

### 2.2 数据与规则中枢（勘察确认）

- 数据加载顺序：`data.js(MOCK) → common.js(UI) → stores.js(Store) → databus.js(用户/钱包/账本) → domain.js(Mediation 状态机)`。
- 平台规则中枢 `MOCK.business`（`js/data.js:1055-1129`）已配置：佣金阶梯、里程碑、保证金三档、意向金、质保金、入驻费、增值道具、监控限额、诚信分阈值等——**规则引擎是齐全的，缺的是承载它们的"平台侧界面"**。
- 交易账本 `Ledger`（databus.js）：买方 available → 平台账户（intent 意向金 / escrow 托管 / warranty 质保金 / platform_income 平台收入），资金守恒可对账。
- 身份门控 `entryAccess()`（stores.js:1005）：中介专属入口（服务经营、服务广场后台入口）只对入驻类型含 `agency` 的用户开放。

**结论**：中介板块是平台"最深交易闭环"的样板间——它证明了平台有能力做"钱不过手、按里程碑释放"的规范交易。因此本轮优化不应削弱这套模型，而应把缺失的"平台视角"补上、把逻辑缺陷修掉、把体验做顺。

## 三、第二步 · 中介服务应有的专业商业模式

### 3.1 价值网（三方 + 资金方）

```
              服务/方案/交付成果
    ┌──────────────────────────────┐
    ▼                              │
 建筑企业(买方)              中介机构(服务商)
    │ ①发现 ②下单托管 ③验收       │ ①挂牌 ②接单履约 ③收款
    └──────────────┬───────────────┘
                   │
             平台(Engchain)
   ┌───────────────┼───────────────────┐
   │               │                   │
 撮合与信任      资金与风控          规则与监管
 金V/信用分/案例  持牌托管/里程碑释放   入驻审核/发布审核/佣金/质保金/纠纷仲裁
```

- **平台本质**：不直接提供服务，做"撮合 + 信任背书 + 资金安全 + 规则执行"。
- **平台收入**（已配置，证据见 `data.js:1063-1111`）：①撮合佣金（阶梯 8%→3%，服务商侧扣，用户侧零扣减）；②入驻费（中介 ¥29,999，破冰期 ¥14,999）；③增值道具（置顶 ¥99/7天、线索包 ¥299/50条、经营工具 ¥199/30天）；④远期：资金沉淀。

### 3.2 信任与风控体系（应有的完整链条）

| 环节 | 机制 | 现状（证据） |
|---|---|---|
| 准入 | 中介入驻两级审核 + 金V标识 | ✅ 有（entry-review.html + entryTypes） |
| 供给质量 | 服务发布审核（pending_review→active） | ✅ 有（SupplyStore.approve/reject） |
| 信用 | 诚信分（评价均分+履约率，基础60+40，默认80） | ✅ 有（svcCreditOf） |
| 交易定金 | 意向金 20% 就近取档，7天提醒/30天自动退 | ✅ 有（intentAmountOf + checkIntentTimeout） |
| 资金安全 | 全款托管至监管账户，按里程碑释放 | ✅ 有（Mediation 状态机 + Ledger） |
| 履约保障 | 里程碑 4 节点（≥5万）/ 整单（<5万），14天自动确认 | ✅ 有（buildMilestones + autoConfirm） |
| 售后保障 | 质保金 5%，验收后 30 天释放 | ✅ 有（warranty + releaseWarranty） |
| 违约防范 | 跳单预警：禁聊7/30天、罚¥5,000、停业15天、二次清退 | ⚠️ 规则已配（jumpContract）但**未发现执行页面** |
| 纠纷处理 | 平台仲裁：disputed → 裁决退还/放款 | ❌ **死胡同**（无裁决动作） |

### 3.3 交易闭环（应有路径）

```
发现 → 决策 → 下单 → 履约 → 结算 → 复购
广场/AI匹配 → 详情/信用/报价/案例 → 意向金锁合作 → 托管+里程碑交付 → 佣金/质保金 → 评价/信用回流
```

## 四、第三步 · 三端执行路径（现状梳理，含已核验代码）

### 4.1 用户侧（买方，建筑企业主）

1. 登录 → 实名（下单前强制校验，order.html 已实现）
2. 服务广场（agency/index.html）：逛分类、搜热门、场景卡 AI 匹配（GOAL_CFG 按目标动态出"当前状态/时限/预算"选项，MATCH_KEY 正则过滤服务）
3. 服务详情（supply/detail.html，from=market 时 CTA=「在线下单」带报价金额；否则「免费咨询」）：报价明细卡、成功案例、材料清单、办理流程、退款/超期条款、机构联系方式（留资后开放）
4. 在线下单（order.html）：选服务商 → 金额（报价带入可改）→ 意向金就近取档 → 里程碑预览 → 支付意向金 → 生成托管单
5. 订单详情（order-detail.html）：意向金流程条/托管资金卡 → 启动托管 → 接单后按里程碑验收 → 终验结算 → 评价
6. 我的单（my-orders.html）：5 状态筛选管理全部订单

### 4.2 服务商侧（中介机构）

1. 中介入驻（entry.html → entry-review 两级审核 → 金V生效）
2. 发布服务（publish/editor.html：仅入驻中介可发，结构化字段 serveType/quote/serveProcess/requiredMaterials/cases/refundPolicy，提交后待平台审核）
3. 服务商工作台（seller-board.html，已按微博创作者中心风格改版交付）：身份头卡（金V+入驻到期）、近7日经营概览、线索管理（LeadStore new/contacted/dealt/invalid）、订单经营（状态/收入/佣金，服务商侧透明）、保证金三档、质保金、我的服务、经营指南
4. 接单履约（order-detail.html 服务商视角）：escrowed 接单/拒单 → serving 提交交付 → 里程碑收款（托管释放）
5. 收款（钱包/提现 withdraw.html）

### 4.3 平台侧（现状：规则有、界面无）

- 入驻审核：EntryStore.approve/pending 方法存在，**无后台 UI**（entry-review 只是申请人视角的进度页）
- 发布审核：SupplyStore.approve/reject 方法存在，**无后台 UI**
- 发票审核：InvoiceStore.approve/reject 方法存在，**无后台 UI**
- 佣金报表：CommissionStore.addFlow 在订单结算时写入，**无任何页面展示**
- 资金监管：Ledger 各账户 + escrowInFlight() 在途托管可算，**无平台视角对账页**
- 纠纷仲裁：disputed 状态存在，**无裁决动作，订单卡死**

## 五、第四步 · 现状诊断（问题清单，全部附证据）

### A. 商业模式缺口（结构性，影响三端闭环）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| A1 | **平台侧无运营后台** | 全项目无平台后台页；审核/佣金/资金/仲裁只有数据层方法 | 三端缺一角，审核与仲裁不可演示 |

| A3 | **托管单无超时接单机制** | intent 有 7/30 天超时；escrowed 无对应机制 | 服务商长期不接单，买方资金无限期冻结 |

| A5 | **跳单规则未执行** | jumpContract 配置存在（data.js:1096），页面无任何引用 | 规则形同虚设 |

### B. 功能逻辑缺陷（影响数据正确性/真实感）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| B1 | **佣金保底 ¥10,000 导致小额单倒挂** | commissionRate（stores.js:985-998）无条件 minCommission=10000；3500 元工商注册单 fee=10000 > 成交额，settle 为负 | 小额订单费用展示与佣金报表数据荒谬（需验证实际影响面） |
| B2 | **评价硬编码 5 分** | order-detail.html:200 `Mediation.review(id,5,t)` | 信用分评价维度失真，用户无选择权 |
| B3 | **服务商评分可能显示 0.0** | order.html normSvc score 默认 0 → `toFixed(1)` = "0.0" | 真实感差 |
| B4 | **佣金两套口径不一致** | create 时 fee 含保底；money() 按 rate 计算 feeReleased；settle 时 CommissionStore 写 `_commissionAccumulated \|\| o.fee` | 报表与页面数字可能对不上 |
| B5 | **里程碑提交后无"提醒验收"** | seller serving 操作只有提交交付/纠纷 | 14 天自动确认前买方可能不知情 |
| B6 | **游客留资无频控** | detail.js 免费咨询留资直接 LeadStore.create | 垃圾线索风险 |
